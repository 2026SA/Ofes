# OFES Ver.1.0 — Firebase Googleログイン・UID確認版

> **重要：この版はFirebase Authenticationの接続テスト用です。会場・プログラム・年度設定の保存先は引き続きブラウザのlocalStorageです。Firestoreへの書き込み処理はまだありません。**

## この版で追加した機能

- 利用者が提供した `ofes-dev` / `ofes-web` のFirebase Web設定情報を組み込みました。
- Firebase JavaScript SDK（ブラウザ向けモジュール）を使ってGoogleログインできます。
- ログイン成功時、Googleアカウントのメールアドレスと **Firebase Authentication UID** を管理画面に表示します。
- UIDコピー、ログアウト、Firestoreの読み取り確認ボタンを追加しました。
- Firestoreはデフォルトの **`allow read, write: if false;` のまま** です。読み取りテストの結果が **「アクセス拒否（正常）」** なら、設定どおり読み取りが拒否されていることを示します。保存の成功を意味するわけではありません。
- Firebase StorageやAnalytics、Firebase Hostingを使用しません。公開先は従来どおりGitHub Pagesです。

## 動作確認手順

1. このZIPの**中身を展開して**、`index.html`、`app.js`、`style.css`、`firebase-config.js`、`firebase-bridge.js`、`assets`フォルダをGitHubの `OFES` リポジトリにアップロードします。ZIP本体だけを置いても公開サイトにはなりません。
2. GitHub Pages（例：`https://2026sa.github.io/OFES/`）で開き、必要に応じてブラウザの再読み込みを行います。
3. ページ下部の **「⚙ 管理者」** を開き、従来の**試作パスワード `ofes0034`**を入力します。
4. 初期表示の **「🔑 Firebase接続」** タブで「SDKの状態：接続準備完了」を確認します。
5. **「Googleでログイン」**を押し、現在開発に利用しているGoogleアカウントでサインインします。
6. **「Googleログイン成功」** と表示され、UIDが現れるかを確認します。
7. **「UIDをコピー」**でUIDを控えます。UIDは管理者の許可リストを作るときに使用します。
8. 任意で **「読み取りを確認する」** を押し、**「アクセス拒否（正常）」**と表示されることを確認します。**Firestoreコンソールのルールは変更しないでください。**
9. テスト後は**「ログアウト」**を押してください。ブラウザを共有している場合は特に重要です。

## Googleログインに失敗した場合

- URLはGitHub Pagesの `https://` 形式で開いてください。`file://` からの起動は対応していません。
- Firebase Authentication → 設定 → 承認済みドメインに `2026sa.github.io` が登録されているか確認してください。
- Googleログインが「有効」になっているか確認してください。
- ポップアップがブロックされた場合は許可してください。学校ネットワークのフィルターによりログイン画面への通信が止まる場合があります。
- SDKが読み込めない場合はインターネット接続とブラウザの開発者ツールを確認してください。

## 残している機能

- 来場者向け3メニュー **プログラム / 会場案内 / スタンプラリー**（ギャラリーなし）
- 学校全体・前期棟1F/2F・後期棟1F/2F/3Fの計6枚のSVG会場案内
- 管理者による会場枠のドラッグ登録、会場とプログラムの紐付け
- 現在およびセッション①〜④の会場表示
- テスト日時と時刻スライダー
- 設定JSONのエクスポート／インポート
- QRコードの `?stamp=1` ～ `?stamp=5` によるブラウザ内スタンプ記録

## セキュリティ・運用上の注意

- `firebase-config.js` にあるAPIキーはWebアプリ用の公開識別情報であり、管理者権限を与える秘密鍵ではありません。
- Googleでログインできることと、**OFESのクラウドデータを書き換えられる管理者に指定されることは別**です。管理者の編集権限は、次の段階で **UIDの許可リストとFirestore Security Rules** により付与します。
- 試作パスワード `ofes0034` はWebページのプログラム内にあるため、**セキュリティ上の秘密やアクセス制限の代わりにはなりません**。この段階ではFirestoreの読み書きがすべて禁止されているため、外部からクラウドデータを編集できません。
- アカウントのログイン状態はブラウザセッション内で保持します。共用端末では明示的にログアウトしてください。
- 今回のFirebaseプロジェクトは**個人の開発用**です。学校用の本番環境を用意したら接続情報・管理者UID・承認済みドメインを見直します。
- 従来のVer.0.9と同じローカル保存キーを使っているため、**同じドメイン・ブラウザ上の既存の試作データ**を引き継げます。ドメインを変えると自動では引き継げないため、JSONエクスポートを使ってください。

## 次に行うこと（Ver.1.1予定）

1. 実際のGoogleログインでUIDを確認する。
2. UIDのみを許可する、限定的なFirestore Security Rulesを設定する。
3. 会場・プログラム設定をFirestoreへ保存し、管理画面から更新して一般利用者の画面に反映する（公開してよい情報の範囲のみ）。
4. 無料プラン（Spark）の読み取り・書き込み枠を踏まえた設計にする。

なお、Firebaseの**実アカウントでのログイン**とFirestoreへの**実通信**は、GitHub Pagesにアップロードした後、利用者のブラウザと権限で確認する必要があります。開発時のローカル静的検証だけでは成功を保証できません。
