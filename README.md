# OFES Ver.0.9｜会場登録＋ギャラリー削除版

## この版でできること

- ユーザー提供の **学校全体・前期棟1F/2F・後期棟1F/2F/3F** のSVGをそのまま会場案内に表示
- SVGのdraw.io編集情報（ルート`content`属性）を削除した公開用画像を同梱
- 管理者が配置図を選択し、会場となる部屋の範囲を**ドラッグして登録**
- 会場の **固定ID・名前・種類・補足** を保存し、名前の修正、位置の再指定、削除が可能
- 登録会場を管理者画面でプログラムに紐づけ
- 来場者画面で「学校全体 → 前期棟/後期棟 → 階」を選択し、会場をタップして予定を表示
- 「現在 / セッション①②③④」で色付けを切り替え
- テスト日時モード（初期値 **2026-11-21 09:25**）、時刻スライダー
- JSON設定ファイルの書き出し・読み込み
- 従来のスタンプURL `?stamp=1` ～ `?stamp=5` のブラウザ内記録

## 管理者画面

試作版パスワード： **`ofes0034`**（年度に依存しない固定文字列）

> このパスワードはフロントエンド内の簡易画面ロックであり、セキュリティ上の認証ではありません。公開GitHub Pages上の本番データ書き込みは、Firebase Authentication と適切な Security Rules を構成してから有効にしてください。

## 動作確認（おすすめ）

1. アプリの「管理者」を開き、`ofes0034`でログイン。
2. 「会場・配置図」で「後期棟2F」などを選ぶ。
3. 「＋ 新規会場」を押す。
4. 図の教室の枠内をマウスまたは指でドラッグして範囲を囲む。
5. 自動で付く会場ID（例：K2-01）を確認し、「会場名」（例：9年生教室）を入力する。
6. 「この会場を保存」を押す。
7. 「セッション①でテスト」を押すと、09:25にその会場で発表するようダミーの紐付けが作られる。
8. 管理画面を閉じて「会場案内」から同じ棟・階を開くと、その会場が緑色に強調される。
9. 会場をタップすると時間・発表内容が下に出る。
10. 管理者「年度・時刻テスト」の時刻を10:00へ動かすと、「現在」タブの緑色が解除される。セッション①タブなら事前に確認できる。

## 保存と更新

この版は**機能確認用のローカル試作**です。変更は実行したブラウザの `localStorage` に保存され、他の端末には共有されません。

管理者画面「データ保存」からJSON形式でバックアップできます。

**今後の実装予定**

- Firebase Auth + Firestore による管理者・来場者間の設定共有
- 校舎配置図はGitHub Pages上に同梱（Firebase Storageを使用しない）
- リアクション5種類と締切・集計
- QRコード入り配布PDFの生成
- スタンプラリーの管理者編集機能
- CSVによるプログラム一括取込・書出

これらは現時点では実装していません。スタンプラリーはローカル動作の最小構成です。ギャラリー（ポスター・動画）は画面・設定・コードから除きました。

## GitHub Pagesへのアップロード

ZIPを解凍し、`index.html`、`app.js`、`style.css`、`assets/`を**OFESリポジトリのルート**に配置してください。

以前のVer.0.7の画面で保存した設定を自動移行しません（保存キーが異なります）。

## 利用にあたって

- 画像上の会場位置は、初回の管理者登録で設定します。図面を自動認識したり、教室名を推定したりはしません。
- SVGは元画像の位置関係を尊重して変更せず、編集データだけ除去しています。
- 日付、会場名称、発表内容などの初期データは試作用です。正式プログラムに置き換えてください。

## Ver.0.9 変更内容

- 来場者向けメニューを **「プログラム」「会場案内」「スタンプラリー」** の3つに変更。
- ギャラリーのポスター表示・YouTube埋め込み・チャンネルへのリンクを廃止。
- ギャラリーに関するデータフィールドを廃止。旧設定／旧JSONを読み込んだときは余分なgallery情報を読み飛ばします。
- Firebase Storageは使用しません。校舎SVG等はGitHub Pagesのファイルから読み込みます。
- 従来のVer.0.8と同じブラウザの保存データ（会場・プログラムなど）を引き継ぎます。
- この版は引き続き試作で、データ保存はブラウザ内です。Firestore連携は未実装です。

## 留意点

次の開発段階でFirebase Firestoreの無料枠を利用して会場・プログラム・リアクションの共有を検討します。
不特定多数の来場者のリアクションを書き込む場合は、レート制限や荒らし対策、無料枠への負荷を考慮してください。
