# OFES Ver.1.3 — Cloud Firestore による公開データの保存・閲覧

## 事前準備（重要）

この版では来場者が Google ログインなしで最新の会場・プログラムを取得します。**公開前に** Firebase Console → `ofes-dev` → Firestore → 「ルール」で、同梱の `firestore.rules` に置き換えて「公開」してください。

- 読み取り公開するのは **`published/site` ドキュメントのみ**。
- 書き込みは UID `XxawqhAFz0SgpzYQbMKMdWQDBNx2` を持つ Google ログインの管理者のみ。Firebaseが発行したログイントークンで照合されます。
- ほかのデータはすべて拒否します。既存の診断パス `ofes_connection_tests/read_probe` は管理者だけ読み取り可。
- UIDが現在の管理者と一致するか、ルールの「公開」前に再確認してください。
- 児童生徒の個人情報や公開できない施設情報は `published/site` に登録しないでください。
- **費用：** Spark（無料）プランの Firestore と Authentication。Storage / Cloud Functions / Firebase Hosting は使用しません。無料枠内での運用を前提とします。

## GitHub Pages への反映

ZIPを解凍し、**中身のファイル**を既存の `OFES` リポジトリにアップロードしてください。
`firestore.rules` と `README.md` は **Firebase設定用の資料**で、Webアプリの動作に不要です。GitHubにアップロードしなくて構いません。

## 管理者操作（おすすめの順番）

1. GitHub Pagesでアプリを開き、管理画面（既存の画面パスワード `ofes0034`）へ入ります。
2. 「Firebase接続」タブで **管理者のGoogleアカウント**でログインします。
3. 「会場・配置図」「プログラム」「年度・時刻テスト」で内容を編集します。ここでの編集は **ブラウザ内の下書き** に保存され、まだクラウドには送信されません。
4. 「データ保存」タブで **「下書きの設定JSONを書き出す」** を押し、バックアップを取ります。
5. 同じタブで内容・登録数を確認し、「**Firestoreへ公開**」を押します。確認ダイアログで確定すると `published/site` が更新されます。
6. 管理画面を閉じると、一般来場者と同じ **クラウド公開済みデータ** が表示されます。
7. 別のブラウザやスマートフォン（Googleログイン不要）でサイトを開き、同じ会場やプログラムが表示されるか確認してください。

## 旧バージョンからのデータ移行

- **`localStorage` キー `ofes-prototype-v08` は変更していません。** 同じURL・ブラウザなら旧版で登録した教室が下書きとして残ります。
- 既存データは自動でクラウドへアップロードされません。上記の「Firestoreへ公開」を1回実行してください。
- 新しい端末では、初めて管理画面を開いた際に公開済みデータから下書きを作れます。
- 以前のJSONバックアップを取り込む方法も残しています。
- Firestoreの公開済みデータとローカル下書きは **分離**。クラウドからの更新は編集中の下書きを勝手に上書きしません。
- 「公開データを編集用に読み込む」はローカル下書きを置き換えます。実行前にJSONバックアップを保管してください。

## 保存内容

`published/site` は年度、開催日、スローガン、会場枠の座標・名称、会場ID発行連番、プログラムを保存します。形式バージョンと最終更新時刻・更新者UIDも記録します。

**保存しないもの：** 管理者のテスト日時 (`test`)、来場者のスタンプ取得状況 (`STAMP_KEY`)、Googleログイン情報。テスト日時はローカル画面だけで利用し、来場者は実時刻で「開催中」を判定します。

公開前は、既存のデモ／ブラウザ内の設定が表示されます。通信エラー時にはデータが同期されず、画面にもエラーを表示します。編集データはローカルに残ります。

## 本番移行時の注意

このプロジェクト `ofes-dev` は個人の開発用です。学校アカウントへ正式運用を移行するときは、学校の GitHub Pages ドメインを Firebase Authentication の承認済みドメインへ追加し、学校側の管理者 UID へ Firestore ルールを切り替えます。別Firebaseプロジェクトを利用する場合は `firebase-config.js` も更新し、公開済みデータを JSON で移行します。

データの公開は初期段階では手動ボタン方式です。来場者の画面は `onSnapshot` で公開データを購読しており、管理者が公開すると開いている画面も更新されます。利用規模によって Firestore の読み取り回数が増えるため、利用状況タブで定期的に確認してください。リアクション機能はまだ未実装です。
